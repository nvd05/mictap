# mictap

Windows-приложение: непрерывно пишет микрофон на диск кусками, с защитой от потерь.
Позже — локальное распознавание (Whisper на GPU) и слой для ИИ-агентов.
Один пользователь, один ПК, без сервера, без интернета, без облака.

Всё, что зафиксировано здесь, — решено. Не переспрашивать.
Что не зафиксировано и влияет на результат — в WARNINGS.

## Стек (фиксирован)
- .NET 10 SDK, C#, `net10.0-windows`, `Nullable=enable`, `TreatWarningsAsErrors=true`.
- UI: WPF + CommunityToolkit.Mvvm + MaterialDesignThemes (Material Design 3). Трей: H.NotifyIcon.Wpf.
- Звук: NAudio. Захват через `WaveInEvent`, формат 16 kHz / mono / 16-bit PCM.
  WASAPI — только если WaveInEvent не даёт этот формат на устройстве.
- JSON: System.Text.Json. Логи: Serilog, файл.
- Тесты: xUnit.
- Запрещено: Python, ASP.NET, брокеры, БД, облачные API, пакеты сверх списка (иначе WARNINGS).

## Архитектура и расширяемость
- Пайплайн: AudioSource → ChunkWriter (диск) → Transcriber → Sinks. Каждая стадия — отдельный класс,
  связь через System.Threading.Channels. Поток захвата только копирует буфер в канал: ни диска,
  ни lock-ов дольше микросекунд. NAudio переиспользует e.Buffer после возврата из обработчика —
  копировать обязательно.
- Интерфейсы только там, где по Roadmap будет вторая реализация: IAudioSource (микрофон; потом файлы
  с телефона), ITranscriber (Whisper.net; потом другие движки и режимы), ITranscriptSink (файл; потом
  уведомление агента). Нет второго варианта — нет интерфейса.
- Форматы на диске — контракт для агентов: meta.json и transcript.jsonl с полем schemaVersion.
  Менять только с повышением версии.
- Точки под будущее закладывать, не реализовывать раньше Roadmap: режимы corrected / verbatim,
  policy.json, пакетная обработка файлов.

## Данные на диске
- Настройки: `%APPDATA%\mictap\settings.json` — rootFolder, deviceName, chunkSeconds (по умолчанию 60),
  language (ru / ja).
- Логи: `%APPDATA%\mictap\logs\`.
- Модель: `%APPDATA%\mictap\models\ggml-large-v3-turbo.bin`, скачивается при первом запуске.
- Сессия: `<rootFolder>\<yyyy-MM-dd_HHmm>\`
  - `audio\000.wav`, `001.wav`, … — чанки по chunkSeconds
  - `meta.json` — schemaVersion (1), started, device, format, chunkSeconds, appVersion
  - `transcript.jsonl` — строка на готовый чанк: schemaVersion (1), chunk, start, end (секунды от начала
    сессии), text. Правка текста в окне переписывает строку своего чанка.

## Надёжность (обязательно)
- Flush на диск не реже раза в 2 с. Падение приложения теряет секунды, не сессию.
- Ротация чанков без дыр: следующий файл открыт до закрытия предыдущего.
- При старте: если в последней сессии есть чанк с нулевыми размерами в WAV-заголовке
  (незакрытый), починить заголовок по фактическому размеру файла.
- Отвал устройства → запись останавливается, в UI и логе понятная причина, записанное цело.
- Никаких try/catch, глотающих ошибки.

## Формат ответа
Первая строка — статус, без преамбулы:
- VERIFIED — сделано и проверено (чем: build / тесты / запуск).
- OK — сделано, не проверено. Одним словом почему.
- FAIL — не сделано. Причина одной строкой.
- DATA — не хватает данных или доступа. Точный список, что нужно. Задача FAIL, пока нет.
Потом 3–5 строк сути. Без пересказа шагов и списка файлов — это в коммитах.
В конце, только если есть:
- WARNINGS: — требует решения пользователя. Вопросы задавать здесь.
- NOTIFY: — полезно знать, не блокирует.

Отчёт передаётся оркестратору (другой Claude), который проверяет коммиты в `main`.
Пиши так, чтобы по отчёту и коммитам проверка не требовала переспросов.

## Поведение при ошибках
- Не работает — не городить обходные пути и заглушки. Остановиться: FAIL или DATA.
- Нет SDK, пакета, доступа, remote → сразу DATA с точным списком.
- Не маскировать ошибки моком, try/catch, хардкодом.

## Git
- Git-корень — `mictap/`, репозиторий `nvd05/mictap` (public).
- Коммиты сразу в `main`, без фича-веток и PR.
- Коммиты мелкие, по одному законченному шагу: скелет решения; настройки; захват;
  чанки и ротация; починка заголовка; тесты; окно; трей; … Каждый коммит собирается
  (`dotnet build`). Лучше пятнадцать мелких, чем один большой.
- Сообщения: `feat(core): chunk rotation`, `test(core): header repair`, `chore: solution skeleton`.
- По завершении задачи — `git push` в `main`, не ждать команды. В отчёте — диапазон коммитов
  или ссылка на сравнение на GitHub, «Как проверить руками» по шагам, что не вошло.
- Нет remote или доступа на push → DATA.
- Чужие файлы в рабочем дереве не трогать.

## Язык
Ответы — русский, деловой тон, без воды. Код, идентификаторы, комментарии — английский.

## Roadmap

### v0.1 — запись на диск (текущая задача)
UI: выбор папки (запоминается), выбор микрофона, Старт/Стоп, индикатор уровня,
строка статуса (сессия, текущий чанк, записано минут), сворачивание в трей,
закрытие окна во время записи — подтверждение.
Core: захват → чанки → meta.json → починка заголовка при старте.
Тесты: ротация чанков на синтетическом PCM без микрофона, починка заголовка, round-trip настроек.
VERIFIED = `dotnet build` без warnings, `dotnet test` зелёный, приложение запускается.
Микрофон проверяет пользователь руками — три шага описать в README.
Не делать: распознавание, хоткеи, Opus-кодирование, автозапуск.

### v0.2 — живой текст
- Whisper.net + Whisper.net.Runtime.Cuda, модель ggml large-v3-turbo. Скачивание в
  %APPDATA%\mictap\models\ при первом запуске, с прогрессом в UI. Язык — из настроек (ru / ja).
- Финал: готовый чанк → текст → строка в transcript.jsonl {schemaVersion,chunk,start,end,text}.
  В окне — список «Записано», текст серым (черновик), можно править; правка пишется в jsonl.
- Живой текст: кольцевой буфер последних ~10 с в RAM (второй потребитель того же канала);
  каждые 3–5 с распознавать его → строка «Сейчас» в окне, перезаписывается. Индикатор «работает»,
  не финальный текст.
- Распознавание никогда не блокирует запись: упал транскрибер — запись идёт, статус в UI.
- В строке статуса — какой рантайм реально активен: CUDA или CPU. Молчаливый откат на CPU
  запрещён — это WARNINGS в отчёте.
- Тесты: буфер и запись jsonl — юнит; транскрибер — интеграционный на wav-фикстуре с русской фразой,
  синтезированной System.Speech, проверка по ключевым словам; пропускается, если модели нет.
VERIFIED = build, тесты, запуск с микрофоном: слова в «Сейчас» в течение 5 с после произнесения.
VAD и режимы corrected / verbatim — отдельными задачами после приёмки.
