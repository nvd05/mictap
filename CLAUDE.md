# mictap

Windows-приложение: непрерывно пишет микрофон на диск кусками, с защитой от потерь.
Позже — локальное распознавание (Whisper на GPU) и слой для ИИ-агентов.
Один пользователь, один ПК, без сервера, без интернета, без облака.

Всё, что зафиксировано здесь, — решено. Не переспрашивать.
Что не зафиксировано и влияет на результат — в WARNINGS.

## Стек (фиксирован)
- .NET 10 SDK, C#, `net10.0-windows`, `Nullable=enable`, `TreatWarningsAsErrors=true`.
- UI: WPF + CommunityToolkit.Mvvm + MaterialDesignThemes (Material Design 3). Трей: H.NotifyIcon.Wpf.
- Звук: NAudio. Захват через `WaveInEvent`, формат 16 kHz / mono / 16-bit PCM.
  WASAPI — только если WaveInEvent не даёт этот формат на устройстве.
- JSON: System.Text.Json. Логи: Serilog, файл.
- Тесты: xUnit.
- VAD: встроенный VAD Whisper.net (Silero), если версия 1.9.x его отдаёт; иначе Silero VAD через
  Microsoft.ML.OnnxRuntime (CPU). Что выбрал — в отчёте.
- Хаб: ASP.NET Core + SignalR только внутри процесса приложения (FrameworkReference
  Microsoft.AspNetCore.App в MicTap.Hub). Отдельный серверный процесс по-прежнему запрещён.
- CLI: Microsoft.AspNetCore.SignalR.Client, System.CommandLine.
- Запрещено: Python, ASP.NET вне MicTap.Hub, брокеры, БД, облачные API, пакеты сверх списка
  (иначе WARNINGS).

## Архитектура и расширяемость
- Пайплайн: AudioSource → ChunkWriter (диск) → Transcriber → Sinks. Каждая стадия — отдельный класс,
  связь через System.Threading.Channels. Поток захвата только копирует буфер в канал: ни диска,
  ни lock-ов дольше микросекунд. NAudio переиспользует e.Buffer после возврата из обработчика —
  копировать обязательно.
- Интерфейсы только там, где по Roadmap будет вторая реализация: IAudioSource (микрофон; потом файлы
  с телефона), ITranscriber (Whisper.net; потом другие движки и режимы), ITranscriptSink (файл; потом
  уведомление агента). Нет второго варианта — нет интерфейса.
- Форматы на диске — контракт для агентов: meta.json и transcript.jsonl с полем schemaVersion.
  Менять только с повышением версии.
- Точки под будущее закладывать, не реализовывать раньше Roadmap: режимы corrected / verbatim,
  policy.json, пакетная обработка файлов.

## Данные на диске
- Настройки: `%APPDATA%\mictap\settings.json` — rootFolder, deviceName, chunkSeconds (по умолчанию 60),
  language (ru / ja), hotkeys {toggleLanguage, toggleRecording}.
- Логи: `%APPDATA%\mictap\logs\`.
- Модели: `%APPDATA%\mictap\models\` — ggml-large-v3-turbo.bin и ggml-silero-v6.2.0.bin (VAD), скачиваются
  при первом запуске.
- Сессия: `<rootFolder>\<yyyy-MM-dd_HH-mm-ss>\` (до v0.2.1 — `<yyyy-MM-dd_HHmm>`)
  - `audio\000.wav`, `001.wav`, … — чанки по chunkSeconds
  - `meta.json` — schemaVersion 2, starts[] {time, offset}, device, format, chunkSeconds, appVersion,
    languageMarks[] {at, lang} (первая метка — 0 с, язык начала)
  - `transcript.jsonl` — сегмент на строку: schemaVersion 2, seq, start, end, lang, text, edited

## Надёжность (обязательно)
- Flush на диск не реже раза в 2 с. Падение приложения теряет секунды, не сессию.
- Ротация чанков без дыр: следующий файл открыт до закрытия предыдущего.
- При старте: если в последней сессии есть чанк с нулевыми размерами в WAV-заголовке
  (незакрытый), починить заголовок по фактическому размеру файла.
- Отвал устройства → запись останавливается, в UI и логе понятная причина, записанное цело.
- Никаких try/catch, глотающих ошибки.

## Формат ответа
Первая строка — статус, без преамбулы:
- VERIFIED — сделано и проверено (чем: build / тесты / запуск).
- OK — сделано, не проверено. Одним словом почему.
- FAIL — не сделано. Причина одной строкой.
- DATA — не хватает данных или доступа. Точный список, что нужно. Задача FAIL, пока нет.
Потом 3–5 строк сути. Без пересказа шагов и списка файлов — это в коммитах.
В конце, только если есть:
- WARNINGS: — требует решения пользователя. Вопросы задавать здесь.
- NOTIFY: — полезно знать, не блокирует.

Отчёт передаётся оркестратору (другой Claude), который проверяет коммиты в `main`.
Пиши так, чтобы по отчёту и коммитам проверка не требовала переспросов.

## Поведение при ошибках
- Не работает — не городить обходные пути и заглушки. Остановиться: FAIL или DATA.
- Нет SDK, пакета, доступа, remote → сразу DATA с точным списком.
- Не маскировать ошибки моком, try/catch, хардкодом.

## Git
- Git-корень — `mictap/`, репозиторий `nvd05/mictap` (public).
- Коммиты сразу в `main`, без фича-веток и PR.
- Коммиты мелкие, по одному законченному шагу: скелет решения; настройки; захват;
  чанки и ротация; починка заголовка; тесты; окно; трей; … Каждый коммит собирается
  (`dotnet build`). Лучше пятнадцать мелких, чем один большой.
- Сообщения: `feat(core): chunk rotation`, `test(core): header repair`, `chore: solution skeleton`.
- По завершении задачи — `git push` в `main`, не ждать команды. В отчёте — диапазон коммитов
  или ссылка на сравнение на GitHub, «Как проверить руками» по шагам, что не вошло.
- Нет remote или доступа на push → DATA.
- Чужие файлы в рабочем дереве не трогать.

## Roadmap

### v0.1 — запись на диск (текущая задача)
UI: выбор папки (запоминается), выбор микрофона, Старт/Стоп, индикатор уровня,
строка статуса (сессия, текущий чанк, записано минут), сворачивание в трей,
закрытие окна во время записи — подтверждение.
Core: захват → чанки → meta.json → починка заголовка при старте.
Тесты: ротация чанков на синтетическом PCM без микрофона, починка заголовка, round-trip настроек.
VERIFIED = `dotnet build` без warnings, `dotnet test` зелёный, приложение запускается.
Микрофон проверяет пользователь руками — три шага описать в README.
Не делать: распознавание, хоткеи, Opus-кодирование, автозапуск.

### v0.2 — живой текст
- Whisper.net + Whisper.net.Runtime.Cuda, модель ggml large-v3-turbo. Скачивание в
  %APPDATA%\mictap\models\ при первом запуске, с прогрессом в UI. Язык — из настроек (ru / ja).
- Финал: готовый чанк → текст → строка в transcript.jsonl {schemaVersion,chunk,start,end,text}.
  В окне — список «Записано», текст серым (черновик), можно править; правка пишется в jsonl.
- Живой текст: кольцевой буфер последних ~10 с в RAM (второй потребитель того же канала);
  каждые 3–5 с распознавать его → строка «Сейчас» в окне, перезаписывается. Индикатор «работает»,
  не финальный текст.
- Распознавание никогда не блокирует запись: упал транскрибер — запись идёт, статус в UI.
- В строке статуса — какой рантайм реально активен: CUDA или CPU. Молчаливый откат на CPU
  запрещён — это WARNINGS в отчёте.
- Тесты: буфер и запись jsonl — юнит; транскрибер — интеграционный на wav-фикстуре с русской фразой,
  синтезированной System.Speech, проверка по ключевым словам; пропускается, если модели нет.
VERIFIED = build, тесты, запуск с микрофоном: слова в «Сейчас» в течение 5 с после произнесения.
VAD и режимы corrected / verbatim — отдельными задачами после приёмки.

### v0.3 — сегменты по речи, язык, хоткеи
- VAD в пайплайне: звук → сегменты речи (граница — тишина ≥ 500 мс, жёсткий срез на 30 с).
  Распознаются только сегменты с речью: без речи нет вызова Whisper, значит нет «Продолжение следует…».
  Чанки на диске (60 с WAV) не меняются — это хранение; распознавание теперь по сегментам.
- transcript.jsonl schemaVersion 2: `{schemaVersion, seq, start, end, lang, text, edited}`;
  start/end — секунды от начала сессии; правка в окне переписывает строку по seq и ставит edited=true.
- Маркер языка: нажатие хоткея кладёт в поток маркер с временем нажатия; маркер — жёсткая граница
  сегмента; каждый сегмент распознаётся с языком, действующим на его начало. Живой текст на
  переключении сбрасывает кольцевой буфер и дальше идёт новым языком.
- Хоткеи глобальные (RegisterHotKey), работают из трея, настраиваются в settings.json:
  toggleLanguage по умолчанию Ctrl+Alt+L, toggleRecording — Ctrl+Alt+R. Конфликт при регистрации →
  сообщение в UI, не падение. Alt+Shift, Ctrl+Shift, Win+Space не предлагать — раскладки Windows.
- Отклик без экрана: на смену языка короткий сигнал, разный тон на ru и ja; текущий язык виден
  в иконке трея и в строке статуса.
- Надёжность распознавания: сегменты, пришедшие до загрузки модели, встают в очередь, не теряются;
  транскрибер после сбоя перезапускается сам (backoff 1 → 30 с), статус в UI; кнопка «Распознать
  заново» для сессии: прежний transcript.jsonl → transcript.<timestamp>.bak, звук из audio\ прогоняется
  через VAD и Whisper заново с языками по маркерам из meta.json (маркеры там и хранятся: `languageMarks`).
- Тесты: VAD на синтетике (фразы System.Speech + тишина 1 с между ними) → число сегментов и границы
  ±100 мс; маркер режет сегмент; jsonl v2 round-trip и правка по seq; разбор строк хоткеев.
VERIFIED = build, тесты, руками: фраза на русском, Ctrl+Alt+L, фраза на японском — две строки в
jsonl с ru и ja; 30 с молчания — ни одной строки; kill транскрибера (имитация исключения) — поднялся сам.

### v0.4 — проекты и сессии
- Корень по умолчанию `%LOCALAPPDATA%\mictap\projects\`, меняется в настройках. Старые сессии в прежней
  папке не переносить, не трогать.
- `<проект>\project.json`: schemaVersion, name, languages (первый — язык по умолчанию, хоткей
  переключает по кругу), audioRetention: keep | deleteAfterTranscript | none.
  `<проект>\<сессия>\`: audio\, transcript.jsonl, meta.json, agents\, notes\ (пустая, для агентов).
- Имя сессии вводит пользователь, поле предзаполнено yyyy-MM-dd_HH-mm-ss, недопустимые символы
  вычищаются. Дозапись в существующую сессию: нумерация чанков и seq продолжаются, meta.json хранит
  список стартов.
- audioRetention: deleteAfterTranscript — чанк удаляется, когда все его сегменты записаны в jsonl и
  сброшены на диск; none — звук на диск не пишется, UI предупреждает, что «распознать заново»
  недоступно. Текст хранится всегда, настройки нет.
- Починка заголовков при старте — последняя сессия каждого проекта.
- UI: боковая панель проекты → сессии, создать проект / сессию, настройки проекта; текущие проект и
  сессия в заголовке; язык по умолчанию берётся из проекта.
- Тесты: project.json round-trip, имена сессий, дозапись, удаление чанков по retention.
VERIFIED = build, тесты, руками: проект «Японский» (ja, ru; deleteAfterTranscript), сессия, запись,
стоп — audio\ пустая, jsonl на месте.

### v0.5 — хаб и CLI
- MicTap.Hub: Kestrel на 127.0.0.1, порт из settings.json (hubPort, по умолчанию 47310), SignalR hub
  `/agents`. Запускается и гасится вместе с приложением. Порт занят → приложение работает, в статусе
  «хаб выключен: порт занят», не падение. Без аутентификации, только loopback.
- Хаб знает: список проектов и сессий, активную запись, сегменты сессии от seq, присутствие агентов.
  Присутствие = открытое соединение; курсор агента — `agents\<agent>.json` {cursor, lastSeen, policy}.
  В UI список агентов текущей сессии: «ждёт» (соединение открыто), «думает» (вышел N с назад), «ушёл»
  (> 10 мин).
- MicTap.Cli → exe `mictap`. Все команды и `--help` на английском: читать будут агенты.
  `mictap wait [--project P] [--session S] [--agent claude] [--min-words N] [--max-wait SEC] [--from-start]`
  Без --project/--session — активная запись. Висит, пока не выполнено условие, печатает в stdout одну
  JSON-строку `{project, session, reason, from_seq, to_seq, lang_now, segments:[{seq,start,end,lang,text}]}`
  и выходит с кодом 0; reason: first_event | min_words | max_wait | session_stopped.
  Нет ни --min-words, ни --max-wait → отдать при первом же новом сегменте; если непрочитанное уже есть —
  сразу, без ожидания. Оба флага → что раньше. --from-start сбрасывает курсор.
  `mictap status`, `mictap projects`, `mictap sessions --project P`, `mictap tail --session S [--seq N]`.
  Коды ошибок: 2 нет проекта/сессии, 3 хаб не отвечает (mictap не запущен), 4 неверные аргументы.
  Текст --help у `wait` объясняет петлю: вызвать, обработать, вызвать снова.
- Тесты: хаб на случайном порту + CLI как библиотечный вызов: фейковая сессия пишет сегменты →
  wait возвращает дельту; min-words; max-wait отдаёт накопленное; второй вызов начинается с курсора;
  --from-start.
VERIFIED = build, тесты, руками: запись идёт, в Git Bash `mictap wait --min-words 20` → после 20 слов
JSON и выход; в UI агент «ждёт» → «думает».
